## Next observability acceptance gate

Source `fe0a7b4003fb24a6a30412177ac9044f493bf0cf` has tracing bridge prerequisites in Gateway/Customer, but Compose has no collected-trace backend. [Remote](../../libraries/service-support/src/main/java/com/fincore/support/Remote.java) forwards technical correlation; [OutboxPublisher](../../libraries/messaging/src/main/java/com/fincore/messaging/OutboxPublisher.java) currently publishes immutable body/key records without trace headers, and [AuditMessaging](../../services/audit-service/src/main/java/com/fincore/audit/AuditMessaging.java) retains body/coordinates without restoring an incoming trace context. Those source facts do not demonstrate an observed cross-service or asynchronous trace.

The next bounded observability lot should collect one actual hosted PKCE flow through Gateway, its owner HTTP dependencies, committed outbox publication and central consumption. Preserve existing envelope bytes/digests, delivery/financial rows and producer isolation. Any asynchronous context must survive delayed/retried publication after the request ends, with explicit tested parent/link semantics rather than copying a correlation ID into a span label. Verify collection and outage behavior from the stored graph, and keep tokens, bodies, names, raw query/filter values and financial contents out of traces. HTTP route templates and bounded labels must avoid resource/subject cardinality. Six observed dashboards and the remaining audit/action/security inventory retain their separate acceptance gates.
