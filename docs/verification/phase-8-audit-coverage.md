## Next implementation gate

Extend finite action registries beyond Customer ADMIN reads with producing module, actor provenance, resource kind, structured outcome/reason and required durability. Separate a signed authenticated subject from an unknown identity and from a producer-reported actor. Do not parse an unverified JWT or caller header into a trusted actor. Use route categories and opaque references; exclude names, prefixes, bodies, tokens, credentials, card details and statement contents.

For each action family, prove the local transaction or durable publication behavior, central redaction, duplicate/replay handling and failure policy. Cover a successful critical action, a signed-role denial, an invalid/absent credential, a direct-owner attempt and unavailable audit storage. Verify append-only behavior with restricted runtime roles. Record delivery/retention limits explicitly; JSON logs, correlation fields, ACL tests and financial immutability remain distinct evidence.

This inventory identifies remaining work to implement and test. The [Customer registry acceptance](phase-8-customer-read-audit.md) proves one finite action family; it does not certify platform-wide coverage or accept Phase 8. Collected tracing and the six observed dashboards remain separate requirements.
